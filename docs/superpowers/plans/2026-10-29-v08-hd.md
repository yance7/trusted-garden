# Trusted Garden V0.8 HD Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The user approved the design and requested implementation; execute inline, followed by one independent whole-branch review.

**Goal:** Deliver a high-detail, physically shaded farm that preserves V0.8 functionality and provides actual downloadable upgraded assets.

**Architecture:** Three.js/WebGL + TypeScript/Vite, offline-generated GLB and texture resources, stable object metadata, separated UI/simulation/controls. Keep the production baseline in Git; develop in an isolated worktree and validate locally before online integration.

**Tech Stack:** Three.js, Vite, TypeScript, Node test runner, Python/Pillow/NumPy for deterministic texture authoring, Playwright for browser evidence.

**Spec:** `docs/superpowers/specs/2026-10-29-v08-visual-quality-design.md` (approved 2026-10-29).

## Global Constraints

- Preserve V0.8 farm layout, eight views, seven weather states, crop growth, layers, scenarios, guided tour, data drawer, dialogs, snapshot/photo/fullscreen, first/third person and collision semantics.
- Default 2K material maps, selected 4K resources; no external runtime CDN or unlicensed assets.
- Performance/high/photo presets; high visible geometry initially below 3M triangles; never report software rendering as GPU performance.
- Download model and displayed static geometry must share generated assets; every source object appears in the inventory.
- Keep current domain and DNS; no production publication until local visual review.

## Review Focus

1. Model/texture failure must retain a usable loading error and retry; no silent blank canvas.
2. Project subpath and custom-domain root both resolve assets and decoders.
3. Walk-mode keys do not trigger weather/drawer shortcuts; locking loss exits safely.
4. Repeated quality/scene changes do not leak targets or lose semantic visibility.
5. Source normals, transparent surfaces, crop deformation and collision geometry cannot blindly share one conversion path.

## Files and boundaries

- `tools/assets/{source,geometry,materials,build}.mjs`: source reader, high-detail geometry creation, material library, GLB/inventory generation.
- `tools/assets/textures.py`: deterministic physical-scale texture authoring (2K/selected 4K).
- `public/assets/`: generated GLB, materials/maps, source inventory and manifest.
- `src/{main,world,materials,environment,controls,ui,state,character}.ts`: runtime orchestration, assets, PBR setup, weather/light, camera/walk, DOM bindings, pure state/collision, animated character.
- `index.html`, `src/style.css`: preserve the original interface's structure, add only loading/quality essentials.
- `tests/{assets,state}.test.mjs`, `tools/verify-hd.mjs`: asset contracts, behavior, browser regression and evidence.
- `docs/hd-verification.md`: measured results, coverage, pending GPU/artistic acceptance.
