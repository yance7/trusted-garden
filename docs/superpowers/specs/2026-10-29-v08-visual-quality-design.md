# Trusted Garden V0.8：模型与材质体系升级方案

状态：用户已于 2026-10-29 确认实施；在隔离分支开发，线上尚未改动。

追加约束：用户随后明确不限制模型与资源体积，以美观和清晰度优先。原 25 / 60 MB 下载及 512 MB 显存数字不再作为压低画质的门槛；保留能力降级与真实性能报告。

## 1. 目标与已确认方向

用户要求在当前 V0.8 基础上大规模提升所有模型的分辨率、清晰度和建模质量，并已选择「升级模型与材质体系，先给具体方案」。

目标是让农场在全景、设备近景和人物漫游中都具有可信的形体、表面细节和光照，朝高质量实时建筑与农业可视化提升。版本仍称 V0.8；改造包含实际模型资产和网页渲染，不能只改善截图或提高像素数。

「一流水准」是视觉目标，最终以用户对真实浏览器画面的验收为准；技术指标通过不能替代艺术质量判断，也不预先宣称达到影视离线渲染水准。

保留场地布局、系统含义、模拟数据声明、原有视点、导览、图层、天气、作物生长和第一 / 第三人称漫游。界面仅补充画质、资源加载和故障提示所必需的内容，延续原有视觉风格。

## 2. 当前证据与瓶颈

| 项目 | 本次读取结果 | 对升级的影响 |

## 3. 路线比较与选择

| 路线 | 内容 | 收益与代价 |
|---|---|---|
| A：现有渲染器强化 | 保留单文件和自写 WebGL，继续增加程序材质与局部模型细节 | 改动较少，但复杂材质、模型交换和后续维护的实现成本高 |
| B：模型、材质、渲染体系升级 | 整理资产，重建低精度类别，引入标准 glTF 与成熟 PBR 渲染 | 适合全面提升；需要迁移渲染和验证全部交互 |
| C：只提高分辨率与面数 | 全局提高超采样、阴影或细分 | 不补真实细节且增加负载，不满足目标，排除 |

用户选择 B。以下技术细节是执行者建议，随本方案一并确认，不视为用户此前已指定。

## 4. 建议架构

- 使用 Three.js 的 WebGL 渲染、TypeScript 与 Vite，依赖锁定到实施时验证的明确版本。暂不把 WebGPU 或光线追踪作为运行前提。
- 从单文件运行转为同站点的页面、脚本、GLB、纹理和解码器资源；保留 V0.8 原版作为 Git 历史基线。新版本通过本地 HTTP 预览，不再承诺双击单个 HTML 完整运行。
- 以当前 GLB 节点为资产清单起点，建立稳定的对象 ID、区域、图层、作物、传感器和碰撞元数据映射。高精度视觉模型和简化碰撞体分开。
- 新网页使用导出的 GLB 与材质清单；停止维护与 GLB 分离的 Base64 模型副本。运行时新增内容必须有对应源数据 / 生成器；静态模型导出与网页可见资产一致。
- 普通材质用 MeshStandardMaterial；玻璃、湿润涂层、织物等有必要时使用 MeshPhysicalMaterial。高级材质仅按类别启用，避免给每个物体叠加昂贵效果。
- 建立场景、材质、天气、相机 / 漫游、标签 / UI、后处理、资产加载模块，逐项迁移现有行为；不在旧增强层上继续堆叠第三层渲染覆盖。
- GitHub Actions 运行可复现的安装、检查、构建，仍只部署 `dist/` 到 GitHub Pages。支持 `/trusted-garden/` 与现有自定义域名；不改域名和 DNS。
- 所有运行资源同站点托管，不依赖公共 CDN。模型和纹理按区域加载，失败时显示重试与原因，不能留下无提示的空场景。

## 5. 模型升级覆盖范围

先生成完整资产清单，覆盖 GLB 的全部对象和网页动态生成的草丛、人物、鸟群等。每个对象记录类别、近景重要度、原始统计、处理方式、材质、LOD 与验收状态；允许同类共享原型，但不能跳过未出现在主视角中的对象。

| 类别 | 几何 / 材质改造 | 近景验收重点 |
|---|---|---|
| 建筑、温室、棚架 | 按真实尺度增加倒角、型材截面、接缝、底座、连接件；校正玻璃厚度与结构 | 侧光有合理边缘高光，玻璃不发白成整块，不出现悬浮构件 |
| 水池、管线、阀门 | 改善曲面采样、池沿、管件、接口和支架；水面独立材质 | 圆弧不明显折线，接口对齐；波纹、反射与水色尺度可信 |
| 摄像头、传感器、网关、机器人、无人机 | 重建镜头、壳体、散热与安装结构、轮胎和接缝；保留功能位置 | 0.5–2 米视距能辨认用途，不能仍只是无细节方块 |
| 玉米、水培植物、芦苇 | 重做弯曲叶片、叶脉法线、叶缘、穗与苞叶，增加有约束的个体变化 | 叶片近景有曲率和方向，光下有薄叶表现；生长动画和风动无明显穿插 |
| 树木、灌木 | 保留种植位置，替换球团树冠的主要轮廓；补枝干层次、树皮和叶簇 | 全景不再以堆球为主要形态，近景枝叶衔接合理 |
| 草地、土壤、道路、木平台 | 草叶曲面与实例化，裸土 / 草区边界、地表纹理、木纹方向与板缝 | 去除交叉矩形草丛外观；纹理不漂浮，不铺到道路或池内 |
| 漫游人物 | 改善头面、手、鞋、衣服轮廓，补服装 / 装备材质；建立与动作匹配的骨骼蒙皮 | 近景没有明显分离的胶囊关节，脚掌落地；第一人称不露出头部内面 |
| 小型配件与场景生物 | 按清单逐类检查轮廓、法线、材质与远景简化 | 不以全局加面代替逐类审查；保留对象可见性和交互语义 |

硬表面采用适当倒角和正确法线；有机物按轮廓需要重建。正常平面不为追求面数而细分。每个新增零件都核对尺度、连接关系与可见用途，避免无依据的工业细节堆砌。

## 6. 纹理与材质制作

- 建立混凝土、铺装、泥土、木材、树皮、叶片、涂装金属、裸金属、塑料、橡胶、织物、皮肤、玻璃、水等材质族。
- 默认 2K 可平铺材质；建筑主材、树皮、叶片图集与近景设备按实际屏幕占用使用 4K。以纹素密度和可见信息为依据，不把所有对象强制做成独立 4K / 8K。
- 按材质需要制作基色、法线、粗糙度、金属度和 AO；仅颜色贴图使用颜色空间转换，数据贴图保持线性。法线、粗糙度不是把颜色图简单转灰。
- 展 UV、处理接缝、校验纹理方向与实际尺度；重复物体共享图集并提供小幅颜色、粗糙度和形态变化。
- 优先自行制作 / 程序生成资源。确需外部素材时，只使用可核实授权的免费资源，记录来源、许可、作者、修改和用途；不购买素材或使用来源不明的人物 / 植物包。
- 资产制作可采用隔离的 Blender 环境和可重复执行的脚本，不修改系统级安装。若工具取得受阻，先完成可用的替代流程和报告，不能把低精度替代品标为最终高质量资产。
- 优先采用 KTX2 / Basis 压缩与 mipmaps，打包必要解码器；保留可复现源材质与未压缩生成流程。压缩后检查法线、透明边缘与细叶细节。

## 7. 光照与清晰度

- 建立统一线性光照、环境照明与最终显示转换，日照 / 天气共享一套材质响应。
- 环境反射经过预过滤；玻璃和水面各用匹配的方案，必要的局部反射只在可见时更新，性能档降级。
- 校正阴影偏移、接触关系与透明排序。原有按 mesh 序号累加深度偏移不作为真实几何问题的统一解决办法。
- 天气保留雾雨变化，但晴天不应依靠强雾、Bloom 或强锐化掩盖细节。叶片与草地控制高光闪烁和远景噪点。
- 高质量档使用抗锯齿、受控接触阴影与 AO；锐化保持克制。拍照档可在静止时提高采样，不拖慢正常漫游。
- 草木远处减少几何、保持视觉密度；让近景细节增加而不是全场同时堆高面数。

## 8. 建议性能预算与测量规则

以下是初始设计预算，不是当前已取得的性能结果。以本机可验证的桌面 GPU 作为主参考，记录 GPU、浏览器、视口、DPR、分辨率与预热方式。若无法使用硬件加速，必须把 GPU 性能验收列为未完成，软件渲染仅验证正确性。

| 指标 | 高质量默认档 | 性能档 | 拍照档 |
|---|---|---|---|
| 输出基准 | 1920x1080，DPR 上限与内部像素预算共同控制 | 内部动态降分辨率 | 静止截图提高采样，受设备上限限制 |
| 可见三角面预算 | 通常 100–200 万，上限初定 300 万 | 约 35–70 万 | 按拍摄区域加载高 LOD |
| 阴影 | 4096，按场景 / 视距配置 | 2048 或简化 | 仅在资源允许时提高 |
| 材质 | 2K 主体，重点资源 4K | 降一级 mip / 材质效果 | 局部 4K 与更高采样 |
| 帧率目标 | 参考机器预热后以 60 fps 为优化目标，30 秒路径 p95 帧时不超过 33.3 ms 为初始最低门槛 | 在同机进一步改善帧时 | 不作实时帧率承诺 |

首个可交互场景压缩网络传输量初步不超过 25 MB，高质量全场资源初步不超过 60 MB；资源逐区加载。高档 GPU 资源估算初步控制在 512 MB 内；可见主场景绘制调用目标不超过约 300 次，额外反射、阴影等通道单独统计。

全部指标在代表性样区完成后复核，调整要说明画质 / 性能依据，不能悄悄放宽预算来宣称通过。冷启动用受控 20 Mbps 网络、固定延迟和缓存状态记录时间，不承诺未经测量的「秒开」。

实例化用于重复植物、设备原型和草丛，按空间分块做视锥裁剪和 LOD；透明面积、阴影更新和后处理单独测量。设备能力不足时降级材质 / 分辨率并说明当前档位。

## 9. 迁移顺序与阶段交付

1. **建立基线和清单**：固定现有视点、光照和截图；记录对象 / 材质映射、功能契约、运行资源与模型问题。
2. **完成代表性质量样区**：控制亭一角 + 摄像头 / 设备 + 玉米与草地 + 人物，提供同相机、同光照前后对比，验证新渲染器、材质和预算。先证明路线有效，再复制到全场。
3. **全场资产改造**：按类别完成模型、UV、材质、LOD 和元数据；清单逐项关闭，不把样区成果当作全场升级完成。
4. **功能迁移与性能收敛**：恢复全部交互、碰撞、气候、生长、截图、导览；处理透明、动画、远景稳定性与资源加载。
5. **本地视觉验收与发布准备**：交付可访问预览、对比截图、录屏、性能报告、模型与资源说明，再按用户确认的发布范围更新线上。

实施在隔离分支 / 工作区中进行，本地验收前不推送 main 或触发线上发布；当前线上 V0.8 在新版本验收前继续可用。无需新增一个对外版本目录来保留旧版，可用当前 Git 提交恢复基线。

## 10. 验收清单

### 画面

- 8 个原有视点拍同参数全景，4 类代表近景覆盖建筑 / 设备、植被、人物、水体。
- 固定晴天上午、中午、黄金时刻的光照，对比不能靠换相机或换曝光掩盖缺点；另检查阴雨与雾的行为。
- 1080p 与 1440p 桌面、DPR 1 / 2 验证文字和几何；窄屏验证界面可操作及性能降级，不承诺手机达到桌面最高画质。
- 浏览器中录制慢速旋转和第一 / 第三人称移动：无明显闪烁、透明排序翻转、LOD 跳变、阴影漂移、脚滑、穿透。
- 图片对比采用静态种子、固定太阳 / 天气 / 作物阶段；动态风动另录视频。用户以实际预览确认总体风格与细节质量。

### 资产与功能

- 每个模型族有清单条目、处理说明及对应视角；GLB 校验法线、索引、UV、材质引用、动画和边界盒。
- 运行模型与导出资产来源一致；没有「网页看起来变了，但下载模型仍是旧版」的情况。
- 现有 17 组交互回归作为最低覆盖，迁移后加入实际状态断言；另外检查碰撞、W 行走不切天气、第一人称隐藏头部、截图导出和资源失败重试。
- WebGL 正常且页面 / 着色器错误为零；没有丢失的材质 / 解码器 / 网络资源。
- 在真实 GPU 上按固定路径记录帧时、资源量与加载数据；软件渲染结果独立列出。

### 发布

- 锁文件安装与构建通过，GitHub Actions 成功；首页、子路径、自定义域名与资源路径验证。
- 线上与验收构建对应同一提交；保留原 V0.8 基线提交作为回滚点。
- 研究或运行数值继续标注为模拟值，不增加虚构的科研结果或测量。

## 11. 执行者可自行决定的事项

在预算和视觉验收目标内，执行者选择模型生成方法、倒角细分数、贴图生成 / 烘焙工具、压缩参数、批次拆分、LOD 距离、材质微调和测试实现。相关选择应可追溯，不需要逐参数请用户批准。

默认风格提案为自然写实的实时农业 / 建筑可视化，保留现有克制的展示界面；不改成卡通风格。默认优先桌面高画质，并保留可用的性能档。默认只使用免费、授权明确的素材，不需要用户先购买或准备外部资产。

## 12. 风险与处理

- **建模资料有限**：当前没有发现原始建模工程；以现有结构和场景语义重建，不声称恢复了未提供的设计细节。
- **旧合批隐藏对象语义**：用 GLB 节点清单建立映射，再做合批；不能从网页材质名称盲目推断全部设备。
- **人物 / 植被质量不达标**：安排近景专门验收；程序生成只是制作手段，不自动等于高质量，必要时迭代资产。
- **图形工具与 GPU 访问未确认**：实施开始先确认可用环境；工具缺失不作为暗中降低验收标准的理由。
- **渲染迁移引入功能回退**：先锁定行为，再逐模块迁移；视觉改善和功能保持分别验收。
- **资源体积增长**：共享材质、实例化、LOD、按区加载和纹理压缩共同控制；本地资源大于预算时先优化再推广。

## 13. 技术依据

- Three.js [MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)：支持透射、织物光泽等属性，同时明确高级材质有额外成本。
- Three.js [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)：标准 glTF 加载与压缩、物理材质扩展支持。
- Three.js [KTX2Loader](https://threejs.org/docs/pages/KTX2Loader.html)：压缩纹理转码和本地解码器要求。
- Three.js [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)：重复几何与材质的实例化绘制。

本地统计来自本次对 GLB 和 V0.8 HTML 的直接解析，不以历史文档中的结论替代当前证据。
