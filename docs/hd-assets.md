# 高清资产与来源

## 生成关系

网站、模型下载和对象清单使用同一生成流程：原版 `v0.8/trusted-garden-v0.8-model.glb` → `tools/assets/source.mjs` → 几何 / 材质增强 → `public/assets/trusted-garden-v0.8-hd.glb`。

源 GLB 为 Z-up，旧网页实际采用 X,Z,Y 映射。转换同时反转三角形绕序，并用试验田 A 的正 Z 位置作为回归检查。不能用通用 X,Z,-Y 旋转替代。

每个原始对象在 `inventory.json` 中保留 ID、名称、区域、图层、原始 / 输出面数、升级方法和包围盒。高精度模型与简化碰撞体分开。骨骼人物由 `tools/assets/character.mjs` 生成，再导出为独立的 `researcher-v0.8-hd.glb`；网页加载此文件并驱动同一骨架。

## 4K 表面资源

混凝土、木材、树皮与泥土使用 Poly Haven 实拍材质，均为 CC0-1.0。完整下载地址、源文件 SHA-256、许可与修改记录见 `public/assets/textures/sources.json`。使用了 Rough Concrete、Wood Planks Dirt、Bark Brown 02、Brown Mud 02；[许可说明](https://polyhaven.com/license)。

叶片、金属微表面、草皮与草叶卡、水面法线为本项目的程序生成资源；原生分辨率 4096，不以放大小图代替。粗糙度以 G 通道打包；AO 与金属乘数为中性值，具体材料由 glTF 的因子决定。叶片 / 金属 / 草叶卡的打包数据图使用 2048 或 1024，草皮为 2048；基色、法线及四种实拍表面均为原生 4K。

- 叶片贴图是亮度中性的细节图：基色按材质因子着色，alpha 通道只保留叶形剪影。只有真正的叶面 / 草叶卡批次带 `cutout` 标记，运行时对其启用 `alphaTest`，茎秆、穗、须等仍为不透明批次，避免整场植物被同一剪影切穿。
- 草皮（turf）是不透明的剪草地面族，按 2 米一个贴图循环设计：约 16 cm 草行、60 cm 剪草带与低频斑块；场地基座与两侧草带的 UV 改为世界坐标投影，不再把一张贴图拉伸到 38×31 米而生成摩尔纹。
- 金属拉丝法线的频率由每循环 512 条降到 96 条，远处设备表面不再出现白点噪声。

```powershell
# 仅重新生成模型，不访问素材网络：
npm run assets

# 重新制作贴图（需要 Python + Pillow + NumPy）：
npm run author:materials
python tools/assets/water.py
npm run assets
```

`npm run author:materials` 先由 `textures.py` 生成全部程序族，再由 `import-cc0.py` 用 Poly Haven 实拍图覆盖混凝土 / 木材 / 树皮 / 泥土四族并写入来源记录；两步必须连续执行，否则实拍表面会被程序化占位图替换。`textures.py` 的 `REV` 标记决定缓存是否重建，改动生成逻辑后需要同步递增。

原始下载缓存在 `.cache/materials/`，不提交。下载脚本使用用户指定的本地 7890 代理；原始文件在缓存中时直接复用。WebP 转换保留高质量，GLB 使用 Meshopt 压缩几何，运行时解码器来自锁定的本地 Three.js 依赖。

## 程序化模型细节

`tools/assets/geometry.mjs` 与 `build.mjs` 在源模型之上重建可读性最差的几类对象，源对象仍在 `inventory.json` 中保留记录，被替换项的 `method` 以 `superseded-` 开头、输出面数记为 0：

- 玉米：对合并茎秆做连通分量分析，还原 378 株的基点与株高，逐株生成带倾角的茎、9 片弧形叶、果穗 + 4 片苞叶 + 5 束花丝、顶生雄穗（主轴与 6 条分枝）。原来的低模叶片 / 果穗 / 苞叶 / 雄穗整体退场。
- 树冠与灌木：叶片改为双层球壳排布、叶尖外垂，灌木另加 7 根细枝，避免远看为实心球。
- 地被：每平方米 24 张十字草叶卡（alpha 剪影）加 2 簇曲面草叶，配合世界坐标 UV 的草皮贴图。
- 水体：池塘水面改为 40 环 × 72 段的圆盘，顶点波动与法线共同产生涟漪；鱼体下潜并补水平尾鳍；曝气气泡改为水下小球，不再漂浮成白色泡沫。
- 人物：`tools/assets/character.mjs` 修正发色、背心体积与反光条配色。

## 体积与性能取舍

用户已明确不限制模型与材质体积，因此先前方案中的下载量和显存预算不作为降画质理由。性能档保留完整几何与材质，只降低输出 / 阴影和后处理。2026-10-30 加载故障修复加入 KTX2 GPU 纹理压缩与渐进材质加载；没有实现按区几何流式加载或几何 LOD。

渲染侧的当前选择：环境光遮蔽使用 GTAO（0.4 倍内部分辨率、6 采样、混合强度 .55）替换原 SSAO，复用主渲染的深度与法线，约省一半开销；不加 Bloom，本机 A/B 截图证明泛光把全场冲淡成灰白；漫游时阴影视锥收窄到人物周围 ±9 米并按 12 Hz 刷新，退出漫游恢复 ±30 米全场；阴影贴图 High 档为 3072、性能档 2048。

## 网页渐进加载

完整几何 890,860 个三角面、344 个语义批次。入口先加载同一模型、技术员与 25 张 1024px 预览材质（合计约 5.82 MB），进入场景后逐张替换为原尺寸的 KTX2 材质。4K 仍为 4096，草皮与部分打包数据图为 2048 / 1024；原始 WebP 与模型导出引用均保留。高清材质失败只暂停细节升级，界面提供重试，已成功的材质不重下。预览材质暂不可用时使用中性占位，不阻止进入场景。

KTX2 使用 Basis Universal 1.16.3、UASTC level 3、不启用 RDO、离线 mipmaps 与 Zstandard 18。UASTC 是高质量有损 GPU 编码；Zstandard 层为无损压缩，不能将整套编码称为无损。数据图按线性空间处理，法线 mipmaps 重新归一化，颜色图按 sRGB 处理。Three.js 按硬件能力转为 GPU 格式；不支持压缩纹理的设备保留兼容预览，避免自动上传整套未压缩 4K 图造成内存过载。

原 WebP 材质库约 87.84 MB；高质量 KTX2 总量约 244.05 MB，后台完整下载量更大。采用它的目的是保留原生尺寸并降低驻留显存、避免高清下载阻塞入口；首屏不再等待这套资源。GPU 支持 4x4 / 16-byte 块格式时，全部 mipmaps 数据为 420,829,168 字节（约 401 MiB）；不包含其他场景、渲染目标和浏览器内存。

重新制作网页派生材质需便携 `basisu` 1.16.3 编码器，并设置 `BASISU` 为其路径，然后运行 `node tools/assets/delivery.mjs`。编码器只用于作者工作站，不需要安装进系统；`sharp` 固定在开发依赖。CI 使用已经提交的派生材质，不运行编码器。`public/assets/basis/` 的同源解码器来自当前锁定的 Three.js 依赖。更换源贴图后应重新生成对应 KTX2（删除该派生文件或输出到新目录），再运行材质生成命令，不能仅重建预览。

为了兼容常用模型查看器，导入时需同时保留 GLB、textures 目录；素材来源记录建议一并保留。
